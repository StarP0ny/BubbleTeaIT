# Работа с BubbleTeaIT

Общаемся по-русски. Рабочая база этого инструментария — данный репозиторий.

- Перед изменениями читать Git status и документы, относящиеся к задаче.
  Сохранять пользовательские изменения.
- Актуальные документы: `README.md`, `TODO.md`, `docs/project-config.md`,
  `docs/service.md`, `docs/setup.md`, `docs/components.md`.
  Исторические концепции, слайсы и исследовательские материалы хранятся
  локально в `attic/` и в Git не входят.
- `vendor/` — закреплённые upstream-сабмодули. Не редактировать их попутно;
  интеграцию размещать в собственных адаптерах. Обновление ревизий описывать явно.
- Прикладные профили и рабочие проекты — внешние потребители, а не зависимость
  ядра. Их исходники, сабмодули, отчёты, пути и имена не добавлять в Git и
  не изменять в рамках разработки поиска без отдельной задачи.
- Состав проекта выбирает точные версии индексов. Не сливать внутренние
  KV/graph/vector-файлы разных движков. Сохранять путь, строки и версию источника.
- `.local/` содержит локальные снимки и результаты; веса и рабочие индексы
  хранить вне Git. Не переносить туда секреты из внешних проектов.
- Git ignore учитывать по умолчанию. Явный attach сильнее ignore, но не
  явных исключений и границ источника. Не добавлять local в основной корпус
  для курации: использовать отдельную целевую индексацию и внешний skill.
- Скиллы создавать вне репозитория, в настроенном каталоге скиллов.
- Проверять затронутое поведение. Для документации достаточно ссылок и diff;
  не заявлять об успешной интеграции по одному наличию исходников.
